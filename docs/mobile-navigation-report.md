# 手机导航与跳过补学验证

2026-11-07。依据用户指定的左滑前一个、右滑下一个，以及允许未标记跳过后补学。已在本地完成，未提交、推送或部署。

## 手机界面与学习规则

- 手机学习页去掉独立品牌栏，保留顶部单元选择与进度；词条内容居中，前后按钮、滑动提示及“回到学习单元”集中于底部。正文完整，例句按钮至少56px，其他学习操作至少44px；极短视窗/文字放大仍能滚动。
- <=600px 视口下，卡片正文单指左滑前一个、右滑下一个。点击前后按钮也能操作，桌面不要求触摸手势。
- 未标记可跳过；导航只原子保存游标，不自动生成评分。刷新恢复所在词条；返回旧词可播放和修正原标记。
- 单元末尾有遗漏时显示待标记列表和“补学未标记”，从首个遗漏词继续；全部标记才保存完成状态。首页显示每个已浏览单元的待标记数量。
- 完成后的重听仍只读，不修改原记录；最后一项进入本组记录，不自动跨单元。
- 评分未确认保存时，滑动、按钮和底部返回都被阻止。位置保存失败保留原卡片并允许重试。切换词条停止原音频，下一词仍由用户点击播放。

跳过项：既有WebKit跨进程持久化用例仅Chromium执行；新增CDP原生触摸输入用例也仅Chromium执行。WebKit通过Pointer Events事件路径与布局验证，不声称原生触摸实机通过。

TDD证据包括缺少导航API/滑动识别时的失败、浏览器右滑仍停留第1项的失败，以及新增双指误触用例先失败后修复。双指修复让卡片外第二个触点也取消待识别手势。导航专项还验证了保存确认期间连续滑动不会跨过额外词条。

两项测试适配有明确原因：导航异步完成后才开始反向滑动，避免把保存期间正确忽略的输入当作回退失败；短视窗滚动后的边界允许1px舍入误差（曾测得400.34375px），未隐藏或裁切正文。
