## 1. 目标与范围

服务学生当前 EJU 日语考试备考，以准确、自然的声音帮助识别词语、搭配、活用形式和语法表达；兼顾读解词汇回忆及记述搭配积累。V1 不替代完整考试训练，不预测考试分数。

运行形态：iPhone Safari / 主屏幕 PWA。默认盲听，另提供看词回忆。前者隐藏文字、释义和图片，后者显示目标写法但隐藏假名、释义。反馈后显示答案、例句与音频，允许在离开本卡前修正反馈。

学习顺序：到期复习 → 今日新项 → 当日短间隔复习；不让重复失败无限占据当前一组。每组10项；新学默认50项，可选20、30、50；漏学顺延，不累加到第二天。新学配额按学习项去重计算，两种模式不重复占新学额度。

FSRS 初始目标保持率0.9，Again/Good 两档；listen/read 两种模式状态独立，不启用另一个模式的学习记录，直到学生实际使用该模式。短间隔采用10分钟的再次学习步骤；同项当天第三次 Again 后退出自动重排，次日再安排，页面给出“今天先放下，明天再复习”。这是减轻负担的产品规则，不是记忆效果保证。

记录采用 Asia/Tokyo 日期。显示新学数、复习数、待复习数和最近7天分模式自评比例，不称为客观正确率。无评价的播放失败、跳过均不改变记忆状态。

## 3. 实施方案与默认技术决策

## 4. 内容规则

学习项类型：word、phrase、form、pattern。一个目标义项/学习任务一个稳定编号；同一词的多个来源放入来源列表，不因再次摘录重复建立同义项。关联词形不共享掌握状态。

每项保存：原文件与原编号、原笔记、标准写法、假名、基本形（可选）、目标义项、中文解释、原句（如有）、自编例句与翻译、搭配、易混说明、听解/听读解/读解/记述用途、主题、学习包、优先级及依据、核查链接与日期、审核状态及版本。

内容优先级：当前材料造成理解障碍的内容 → 逻辑/态度表达 → 通用学术表达 → 当前主题词 → 其他生活词。高频不得凭模型印象标注；只有来源明确时才能称为真题或原题表达。缺原句时保留待核对状态，自编例句不得冒充原句。

首批已知问题包括：じめ→じめん、うらずける→うらづける（拼写规范，不能制造不存在的发音区分）、わけではない的否定范围、のではないか的语气、考えておいてくれ的解释，以及いかた〜か/AといえB等疑义。最终入库需来源核实，聊天中的初审不等于全部已审核。

规范化、选词、例句、文本核查、语音生成、音频检查、程序开发与代码审核全部由AI执行。没有教师试听的人工作业环节；模型无法可靠判断的项目暂缓，不能通过降低标准凑满50项。

## 5. 音频与 AI 审核

每项指定盲听文本和例句文本。句型必须用完整短句；短语整体生成；句子不能用单词拼接。盲听与例句相同时复用音频。正常、清晰、自然的东京式标准语为目标；默认不使用机械慢速、假名逐字念法或浏览器临时合成替代正式音频。

开发时使用支持文件输出的 OpenAI 语音能力，执行前查当前官方文档并通过可用密钥工具接入。ChatGPT 订阅不被视为 API 额度。预设模型名称不写死在业务逻辑中；记录实际模型、声音、提示、时间、输入及文件哈希。

审核分三层：

1. 权威读音资料和语境义校验；音调标注没有依据则不显示。
2. 文件技术检查：可解码、非空、峰值/静音/时长异常、文本到文件映射、资源完整性。
3. 两次独立 AI 音频评审：评审者直接接收真实音频、规范文本与核查依据，不接收生成者自评或另一评审结论。逐条判断漏读/添读、读音、长短音、节奏、明显音调问题及自然度。模型服务相同也可隔离上下文，但必须披露相关错误风险。

两次结论均 pass 且技术检查通过才可标记 `ai_passed`；任一 uncertain/fail 均隔离。无法直接输入音频时返回 unavailable，不以转写或文件存在替代听审。转写只作辅助。

单项自动重生成最多2次；仍失败则暂缓。先5项验证最小学习闭环，再20项声音试验，通过后扩至50项；可用已审核项不足50时交付实际数量和原因，不能伪造通过。全部正式音频均逐项审核。

`ai_passed` 是流程结论，不是母语者认证或绝对正确保证。界面统一标注“AI生成音频，已通过AI检查”，保留“报告内容问题”入口（本地记录，不自动对外发消息）。

正式发布格式MP3；高质量母版放构建产物目录，不随网页全量加载。总发布音频不超过500,000,000字节；按需加载。修正内容/音频生成新文件哈希，不改变学习项编号。目标义项改变时创建新编号，旧状态不得直接继承。

## 6. 状态、服务与同步

固定PIN服务端验证，生产环境使用HTTPS、安全HttpOnly会话；不注册账号，不允许匿名读取或写入进度，不在浏览器放API密钥。单用户固定 profileId，不将客户端传入的profileId作为授权依据。PIN哈希与会话密钥来自服务端配置。

学习结果写为不可变事件，含eventId、itemId、mode、rating、occurredAt、expectedRevision、contentVersion、可选replacesEventId。服务端事务检查版本、去重并更新FSRS快照；重复eventId且载荷相同返回既有结果，载荷不同返回409。纠正事件只替换该学习项/模式的最近有效评价，并从评价前状态重算；纠正不增加完成数。

客户端乐观更新和持久化待同步队列使用同一调度适配器。网络重试保留事件时间、编号与载荷，逐条发送。401保留队列并提示重新输入PIN；409拉取最新快照，保留冲突事件但暂停该项自动重放，提示“进度已更新，此条需要重新复习”，不静默覆盖。

离线只承诺已缓存应用与资源可用；未缓存音频显示离线不可用，不能伪装成已播放。会话固定内容版本；更新包下载验证成功后下一组生效，缓存中旧音频不能与新文本串配。个人API响应不得被Service Worker公开缓存。

## 7. 验收与授权边界

通过标准：真实内容可完整学习、两种模式独立、复习调度合理、失败播放不记成绩、重复/纠正/断网不损坏数据、音频逐项有AI证据、包映射完整、无已知阻断问题。

AI可运行浏览器自动化、移动视口和WebKit测试；模拟结果不能写成真实iPhone验收。若没有已连接且可控制的iPhone，记录“真机验证未执行”，不安排用户必须完成的开发任务，也不声称完全通过iOS硬件验证。

七天试用属于可选的真实学习效果观察，允许先交付功能版本；不能靠加速系统时间证明七天记忆效果。成本、付费生成、账号授权和公开部署依现有授权执行；额度/权限不明时先交付本地版本及部署候选，不擅自购买或发布。

## 8. AI 时间规划

时间指单一AI主执行者的有效工作时间，包含工具往返、编码、测试、一次修复循环；不是人类工作日，也不是模型吞吐承诺。后台生成与独立开发可重叠，不能简单按代理数除以总时长。

内容计划：2.5—5小时；应用计划：5—9小时；合计7.5—14小时，预留约25%返工后按10—18小时排程。以上未实测；完成首个内容/功能任务后据实际吞吐重估。

可点击骨架约1—2小时；带少量已检查真实音频的本地学习版约3—6小时；首批内容、复习、同步和自动验证完整的候选版约10—18小时。前提是连续运行、服务/运行环境可用及生成额度已授权。账号等待、配额限制、无法访问核查来源、不可用真机均单列，不以固定日历承诺掩盖。
